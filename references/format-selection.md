# 表达形式与结构选择

## 基础结构

默认优先使用用户习惯的结构。没有既有习惯时，可从以下内容中按需选择：

1. 需求背景
2. 需求详情
3. 页面或操作位置
4. 业务规则或流程
5. 异常及边界
6. 验收标准

不要为了完整而全部加入。

## 选择规则

| 内容特点 | 推荐形式 |
|---|---|
| 背景、目标、简单规则 | 简洁文字 |
| 多个对象、字段或前后对照 | 表格 |
| 多步骤或多角色操作 | 流程图 |
| 状态变化和状态限制 | 状态流转说明或图 |
| 页面入口和操作位置 | 页面路径 |
| 原数据与复制数据的关系 | 映射表加简短示例 |

图表只在能减少理解成本时使用。图表后仍要用一句话说明结论，不能只给图不解释。

## 不使用条件

- 只有一个简单操作和一个结果时，不生成流程图。
- 对象少、关系简单时，不为了形式添加表格。
- 页面位置明确且没有分支时，使用页面路径和文字即可。
- 不要同时生成多张表达同一件事的图表。

一个需求可以混合使用多种形式。例如背景用文字，页面入口用路径，原对象与新对象用映射表，只有存在多分支操作时才增加流程图。

## 映射信息的按需完整度

当映射关系会影响开发或验收时，至少写清源对象、目标对象、替换位置、映射方向、触发时机和预期结果。只有涉及持续同步、重复复制、用户修改、解绑或冲突时，才补充关系是否持久化、生命周期和冲突处理。

## 推荐的验收表达

使用“当……时，用户……，系统应该……”描述可观察结果。复杂需求优先覆盖主流程、失败处理和数据独立性，不要机械罗列大量测试用例。
