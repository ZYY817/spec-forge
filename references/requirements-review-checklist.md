# 需求检查清单

提交需求单前，根据实际范围检查：

- 是否说明了背景和要解决的问题？
- 是否写清楚用户在哪里、通过什么入口操作？
- 是否区分了用户目标和实现方案？
- 是否明确了当前要做什么、暂时不做什么？
- 是否把用户已经确认的结论写成了确定内容？
- 是否标注了真正影响结果的假设或待确认事项？
- 如果存在“提示、同步、关联、映射”等歧义，是否先区分页面行为和数据行为？
- 需求仍在讨论时，是否避免提前输出正式需求单？
- 业务对象之间的关系是否清楚？
- 涉及复制、关联、替换时，是否写清原对象、新对象、替换位置和最终结果？
- 是否覆盖关键的异常、边界和失败情况？
- 验收标准是否可以被开发和测试直接验证？
- 内容是否与需求复杂度匹配，没有堆砌无关章节？
- 表格或流程图是否确实帮助理解？

如果有截图：

- 是否区分了截图事实、用户说明和模型推断？
- 是否写清截图对应的页面状态和视觉位置？
- 是否避免仅凭截图臆测对象之间的关联？

如果是 AI Coding 需求，还要检查：

- 是否需要分析现有项目后再选技术方案？
- 是否说明模块边界、复用和测试要求？
- 是否可以拆成分阶段、可验证的开发任务？
