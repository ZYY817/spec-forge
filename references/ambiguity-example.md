# 歧义需求处理示例

## 输入

用户说：“复制后加个提示，提醒用户重新选择物品。”同时提供复制入口和详情页截图。

## 不应直接做的事

不要马上生成“增加提示”的正式需求单，因为这句话可能代表两种不同问题：当前复制逻辑不变，只提醒用户手动处理；或者复制后的数据关联不正确，需要通过源对象和新对象映射自动替换。

## 正确讨论方式

先说明：

```text
我理解当前有两个可能的问题：一是用户不知道复制后需要重新选择，二是复制后的详情配置仍关联原对象。两者的实现和验收不同。这里是只做提示，还是需要长期通过映射自动替换关联？
```

用户确认后再写需求单。若最终只保留映射方案，文档应删除短期提示方案，不能把两个方案混成一个当前交付目标。

## 映射写法

至少写清：

```text
原物品 A1 → 新物品 B1
原物品 A2 → 新物品 B2
礼包 B 的商品售卖物品组合：用 B1、B2 替换 A1、A2
```

数量、标签等不涉及本次变化的配置，说明沿用现有逻辑即可，不必重新罗列全部系统字段。
